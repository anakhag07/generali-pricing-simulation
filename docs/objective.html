491    def _acceptance_penalty(self, acceptance: np.ndarray) -> tuple[float, float]:
492        """Return ``(penalty_value, d penalty / d mean_acceptance)``."""
493        if self.acceptance_floor is None or self.acceptance_penalty_weight is None:
494            return 0.0, 0.0
495        mean_acceptance = float(np.mean(acceptance))
496        gap = float(self.acceptance_floor) - mean_acceptance
497        temp = float(self.acceptance_penalty_temperature)
498        scaled_gap = gap / temp
499        soft_gap = temp * float(np.logaddexp(0.0, scaled_gap))
500        sigmoid_gap = 1.0 / (1.0 + np.exp(-scaled_gap))
501        weight = float(self.acceptance_penalty_weight)
502        penalty_value = weight * soft_gap * soft_gap
503        penalty_grad_mean = -2.0 * weight * soft_gap * sigmoid_gap
504        return penalty_value, penalty_grad_mean

Pricing objective backed by trained ML models.

$$f(u; x) = a(x,u) \cdot (\hat{Y}(x) - (u + 1) \cdot p(x))$$

where $$a(x,u)$$ is acceptance derived from the bundled acceptance classifier, $$\hat{Y}(x)$$ is the expected financial loss (LinearRegression or XGBRegressor), and $$p(x)$$ is the policy premium extracted from column premium_col of x. The policy output u stays centered at 0, so u = 0 means the baseline premium multiplier and revenue uses (u + 1) * p(x).

acceptance_model expects a raw DataFrame with acceptance_state_cols + ["U"]; for the canonical 052726 artifacts class 1 is direct acceptance probability. loss_model expects a raw DataFrame with loss_cols. When GLM coefficients can be extracted from the artifacts, value/acceptance calls use the equivalent array formula instead of repeated sklearn predictions.

If u_coef is provided for GLM artifacts, it overrides the artifact's $$d\,\text{logit}(p_{accept}) / dU$$ coefficient in both acceptance values and analytical gradients. Otherwise the extracted artifact coefficient is used; unsupported artifacts fall back to numerical central finite differences.

When acceptance_floor and acceptance_penalty_weight are both set, value() adds a smooth mean-acceptance penalty. When lagrangian_lambda is set, value() optimizes the scalarized target $$J(\theta) + \lambda (\text{floor} - \bar{a}(\theta))$$ while base_value() keeps exposing the raw pricing objective $$J(\theta)$$ for reporting. Direct trust-region constraints are handled at the optimizer level via step_rule="trust-constr".
